1. Problem and product

The Bern Economic Development Agency connects companies with research partners. An analyst today reads dozens of institute websites in German, English and French to find the right group, and has little to show as proof. Bern Match turns the company's need, written in plain language (EN/DE/FR/IT), into a shortlist of contacts: research groups, labs, platforms, projects and people at the University of Bern, ARTORG and the Diabetes Center Berne. Every card quotes the exact sentence from the source page with its link. The analyst collects entries across several searches into a shortlist, adds notes and exports a PDF for the team. Optional Apertus drafts (one-page brief, e-mail) are labelled as AI and are never sent by the system.

2. Architecture

Offline. A bounded crawl stores page versions and sentence-level text. Apertus 70B reads each page as numbered sentences and returns people, units, projects, infrastructure, roles and relations, each citing sentence numbers. Code maps the numbers to stored sentence IDs. Names must appear in the cited sentence and roles must be verbatim. Contacts are read by regex, never from model text. A group's expertise is never transferred to its members, and instruction-like page text is withheld (prompt-injection guard). A rule check plus a 70B judge then decides whether the cited sentences really state each claim: 4,314 of 5,130 extracted claims passed, 816 were rejected (469 by rules, 347 by the judge). Same-name person entities are merged through T08 aliases (A6), which removed 56 duplicate cards. The index is one SQLite file plus vectors, about 138 MB, and it restores in ≈ 7 s.

At query time. BM25 and multilingual-e5-small run in parallel, are max-aggregated per entity before weighted reciprocal-rank fusion (BM25 weight 0.25), and are diversified with MMR. News, fact-sheet and navigation pages are not shown as contacts. A deterministic policy labels each answer confident, low confidence, too broad or no evidence. In the background, Apertus 70B interprets the request into editable needs, research terms in English and German, and a scope verdict. A second retrieval over those terms produces a refined ranking that never overrides a refusal or a too broad outcome. 8B writes per-candidate assessments, which are validated against the candidate's own evidence. If Apertus is slow, 8B takes over interpretation after 12 s; if it is down, the fast results stand.

4. Technical rigour: evaluation

Protocol. The gold set has 36 real partner-search questions grouped by intent: professional, lay, synonym, misleading, partial and absent, in EN/DE/FR/IT/RU. Expected entities are keyed by source URL. Intent groups are split 17 development / 19 evaluation. The set was frozen (gold 0.3, hash 340c4b0a…) before any evaluation-split run. Every threshold and weight was chosen on development; each evaluation configuration was scored once. One evaluation intent viewed before a re-score is disclosed and was not used for tuning.

Support of evidence (semantic). Quotes are verbatim by construction, but a verbatim quote can still be off-topic. Three samples of 40 cards each were rated supported / partly / unsupported:

  • The baseline cards, AI pre-rated and every rating reviewed by Ruihan: 5% / 12.5% / 82.5%. In 28 of 33 unsupported cases the shown sentence was a heading or fragment.
  • The current cards rated by two independent model judges: 15% / 28% / 57% and 7.5% / 50% / 42.5%, agreeing on 31 of 40.

Strong matches sit at ranks 1–3, and ranks 4–10 are mostly weak. This is our main quality gap (section 8). An assessment sample (10 live, stratified) had the category right in 6 of 10, with no invented contacts or numbers.

5. Value, cost and scalability

  • Latency.
    • First results: server median ≈ 0.26 s, p95 ≈ 0.5 s.
    • 10 concurrent users: p95 ≈ 3 s (load test, 18 Oct).
    • Apertus refinement and assessments: median ≈ 14 s, p95 ≈ 17 s after the B1 latency fixes (parallel batches, interpretation cache, straggler deadline). Before them: 33.5 s / 50.5 s.
    • The analyst never waits for the model: results are shown first, and the refined ranking is offered when it arrives.
  • Tokens.
    • 0 per plain search.
    • ≈ 1.7k input + 1.2k output per refined request.
    • Processing the whole corpus: ≈ 1.05M input + 0.39M output tokens, run once and cached. Re-runs touch only changed pages.
  • Hosting dominates cost. The demo Space (CPU Upgrade) costs ≈ USD 22 per month. Keera token prices are not public to us, so we report tokens and formulas (docs/costs.md).
  • Scaling.
    • The fast path is CPU-only and stateless per request. Scaling means replicas over one read-only index.
    • The index rebuild is incremental: unchanged text reuses its vectors. The person merge re-encoded 31 entries in 41 s.
    • Apertus calls are bounded per request: at most 8 candidates, concurrency 4.

6. Sovereign deployability

  • Swiss model on Swiss compute. Apertus (Swiss AI Initiative) is served through the organisers' Keera gateway on CSCS. No non-Swiss LLM is used anywhere.
  • Open, replaceable components. FastAPI, SQLite FTS5, ONNX Runtime, multilingual-e5-small (MIT) and Apertus (Apache-2.0 per its model card). The LLM endpoint is a single OpenAI-compatible base URL, so a local llama.cpp server can replace the gateway.
  • One command. docker compose up runs the same image as the live Space, restores the index bundle, binds to localhost only and never crawls. A profile adds a local Apertus 8B (community Q4_K_M GGUF, about 7 tokens/s on a laptop CPU).
  • Shown so far:
    • the fast path on the real index with every outbound socket refused: 0 connection attempts, 255 ms for an unseen German query;
    • an in-container check script that proves egress is blocked.
  • Not shown: a recorded air-gapped run with the network switched off at OS level, and local Apertus on the query path. This is a declared gap (decision D13).

7. Responsible by design: crawling, data, AI text

Polite crawling

  • robots.txt obeyed; if unreadable, the site is not crawled (fail closed); no redirects outside the allowed domains.
  • At most 0.5 requests per second per host, identifying User-Agent, back-off on 408/429/5xx with Retry-After honoured.
  • Fixed budgets per source (pages, depth, sitemaps, discovered URLs, 10 MB per response); cached pages reused.
  • No fetch at query time: searches read only the stored corpus.

Data minimisation, removal, retention

  • Only public professional pages from the supplied sources. Contacts are shown only through an official-contact field, never quoted from text.
  • Company descriptions are not stored and kept out of logs; logs are kept 30 days.
  • Removal on request: suppressed records are skipped by the crawler, filtered at serving time and answered with 410. Stored copies are purged within 30 days (proposed retention). The contact address is still to be published.
  • Evidence older than 365 days is marked stale. Former staff are never shown as current; 20 persons were marked from their own pages.
  • AI text is always labelled; e-mail drafts are never sent.

Fair discoverability. Scores are max-aggregated per entity, so a group with one page competes on equal terms with a page-rich institute. Across 350 served cards, 34 of 41 sources appear and no single host dominates (largest 15%). There is deliberately no equal-exposure quota: relevance comes first. Legal. Built for the Swiss nDSG and the GDPR where applicable: only public content, data minimisation, removal and retention as above,. Copyright of the source pages stays with the institutions; we store sentences only to quote and link them. Outputs are to be published as Open Commons per the challenge terms (§6).

These are design commitments, not a claim of legal compliance.

8. Implementation feasibility, readiness and limits

Operation. One-command deploy with smoke test and commit check; rollback by restoring the previous bundle. Feedback and admin state survive restarts; rate limiting; protected admin with per-source coverage. CI runs 360+ deterministic tests with no network and no paid inference. A new source is a YAML file validated by the loader (example: BFH engineering research).

Needed for production: Swiss or on-premises hosting; scheduled refresh crawls; monitoring and alerting; single sign-on; a staffed removal contact; a recorded air-gapped acceptance run; partner review of the gold set (it was written by the team).

Limitations.

  • Small samples: 17 scored evaluation queries, one location for latency.
  • Structured fields cover 26% of cards; every card has quote and link.
  • Ranks 4–10 are often weak matches.
  • The 2 "no answer" questions still return low-confidence cards.
  • The same project can appear twice through its DE and EN pages.
  • French and Italian source content is sparse.
  • The local Apertus model is an unofficial conversion.

Next.
